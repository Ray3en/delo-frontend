React Занятие 01

Интерфейс как функция данных

Компоненты

Кнопка, форма, карточка задачи — отдельные части интерфейса, которые можно переиспользовать.

Декларативность

Описываем, что показать для текущих данных. React применяет необходимые изменения к DOM.

Состояние

Компонент хранит данные между рендерами. Их обновление через setter запрашивает новый рендер.

Компонентный подход Занятие 01

Разбиваем страницу на части

App
├── Header
└── TaskTracker

Обратите внимание

Компонент выделяют по смыслу и повторному использованию. Не каждый HTML-тег должен стать компонентом.

Компонент Занятие 01

Функция, которая возвращает JSX

export default function App() {
  return (
    <main>

  • Имя компонента начинается с большой буквы: App, TaskItem.
  • Компонент используем как тег: <App />. Сохраните файл и посмотрите результат.
JSX Занятие 01

Похож на HTML, но это JSX

Один корень

Оборачивайте соседние элементы в общий тег или фрагмент <>…</>.

Закрытые теги

Закрывайте все теги, включая одиночные: <input />.

Имена атрибутов

className вместо class, htmlFor вместо for. События пишутся в camelCase: onClick.

<>
  <label htmlFor="task">Новая задача</label>
  <input id="task" className="task-input" />
</>
JSX Занятие 01

Данные внутри фигурных скобок

export default function App() {
  const name = "Анна";
  const count = 3;

  return <h1>{name}, задач на сегодня: {count + 1}</h1>;
}
Обратите внимание

В { } можно подставить выражение: переменную, вызов функции или вычисление. Объект целиком не выводят: используйте его поля.

Props Занятие 01

Передаём данные в компонент

type TaskItemProps = { title: string };

function TaskItem({ title }: TaskItemProps) {
  return <li>{title}</li>;
}

export default function App() {
  return <ul><TaskItem title="Изучить JSX" /></ul>;
}
Обратите внимание

Props приходят от родителя. Компонент читает их, но не изменяет. Тип описывает, какие данные ожидаются.

Списки Занятие 01

Массив превращается в элементы

const tasks = [
  { id: "1", title: "Создать проект" },
  { id: "2", title: "Изучить JSX" },
];

// В JSX компонента:
<ul>
  {tasks.map(task => (
    <TaskItem key={task.id} title={task.title} />
  ))}
</ul>
Обратите внимание

key — устойчивый идентификатор среди соседних элементов. Не создавайте случайный key при рендере и не используйте индекс для изменяемого списка.

События Занятие 01

Передаём обработчик

function HelloButton() {
  function handleClick() {
    alert("Привет, React!");
  }

  return <button onClick={handleClick}>Нажми меня</button>;
}

Верно

onClick={handleClick} — функция будет вызвана при клике.

Ошибка

onClick={handleClick()} — функция вызывается уже во время рендера.

Состояние Занятие 01

useState: память компонента

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(prev => prev + 1)}>
      Нажали: {count}
    </button>
  );
}
  • count — значение текущего рендера; setCount — функция обновления.
  • Хуки вызывают на верхнем уровне компонента, вне условий и циклов.
Рендер Занятие 01

Что происходит после клика

01 · Событие

Пользователь нажимает кнопку. Обработчик вызывает setCount.

02 · Рендер

React снова вызывает компонент с новым состоянием и получает JSX.

03 · Обновление DOM

React применяет необходимые изменения. Браузер отображает новый результат.

Обратите внимание

Обычная переменная не запрашивает рендер. Setter задаёт состояние для следующего рендера: в текущем обработчике значение остаётся прежним.

Мини-практика Занятие 01

Проверяем понимание

  • Добавьте к счётчику кнопку «Сбросить», которая устанавливает 0.
  • Что произойдёт, если вместо setCount просто изменить обычную переменную?
  • Почему onClick принимает функцию, а не результат её вызова?
  • Где хранить текст поля ввода, если от него зависит интерфейс?
Практика Занятие 01

Собираем Task Tracker

Минимальная версия: пользователь вводит текст и добавляет задачу в список без перезагрузки страницы.

  • Храним массив задач и текст поля в состоянии.
  • Выводим задачи отдельными компонентами TaskItem.
  • Добавляем задачу через форму; пустой ввод игнорируем.
  • После добавления очищаем поле. Данные пока живут только в памяти.
Практика · 01 Занятие 01

Описываем данные

type Task = {
  id: string;
  title: string;
  done: boolean;
};

// Внутри App:
const [tasks, setTasks] = useState<Task[]>([]);
Обратите внимание

Task[] означает массив задач. Поле done подготовим для домашней работы. Текст новой задачи возьмём прямо из input.

Практика · 02 Занятие 01

Добавление задачи по Enter

<label htmlFor="task-title">Новая задача</label>
<input
  id="task-title"
  onKeyDown={event => {
    if (event.key === 'Enter') {
      addTask(event.currentTarget.value);
      event.currentTarget.value = '';
    }
  }}
  placeholder="Например, изучить JSX"
/>
  • Значение читаем прямо из event.currentTarget — текущего input.
  • После добавления присваиваем input пустую строку. Дополнительное состояние для текста не требуется.
Практика · 03 Занятие 01

Добавляем новую задачу

// Внутри App, до return:
function addTask(newTitle: string) {
  const trimmed = newTitle.trim();
  if (!trimmed) return;

  const newTask: Task = {
    id: crypto.randomUUID(),
    title: trimmed,
    done: false,
  };
  setTasks(prev => [...prev, newTask]);
}
Аргумент функции

addTask получает текст новой задачи через newTitle. Поэтому функцию можно вызвать из поля ввода, кнопки или другого компонента.

Состояние массива Занятие 01

Создаём новый массив

Не изменяем старый

tasks.push(newTask) меняет существующий массив. Не мутируйте состояние напрямую.

Возвращаем новый

setTasks(prev => [...prev, newTask]) копирует прежние элементы и добавляет задачу.

// prev — предыдущее состояние из очереди обновлений
setTasks(prev => [...prev, newTask]);
Обратите внимание

Когда новое состояние зависит от предыдущего, удобно передать setter-функции обновляющую функцию.

Практика · 04 Занятие 01

Что происходит при нажатии Enter

01 · Ввод

Пользователь печатает текст. Значение хранит сам input.

02 · Клавиша

Обработчик onKeyDown проверяет event.key.

03 · Добавление

addTask получает event.currentTarget.value и добавляет задачу.

04 · Очистка

После добавления значение input меняется на пустую строку.

Без формы и отдельного state

Для этого примера достаточно обработчика клавиатуры. Состояние храним только для массива задач.

Практика · 05 Занятие 01

Показываем список и пустое состояние

{tasks.length === 0 ? (
  <p>Пока нет задач. Добавьте первую!</p>
) : (
  <ul>
    {tasks.map(task => (
      <TaskItem key={task.id} title={task.title} />
    ))}
  </ul>
)}
Обратите внимание

Тернарный оператор выбирает один из двух вариантов JSX. Здесь tasks — состояние App, а TaskItem — компонент из примера с props.

Проверка практики Занятие 01

Работает ли наш сценарий?

  • При пустом списке видна подсказка.
  • Задача добавляется и кнопкой, и клавишей Enter.
  • Строка из пробелов не добавляется; после успеха поле очищается.
  • Несколько задач отображаются в порядке добавления; в консоли нет ошибок key.
  • После перезагрузки список пуст: сохранение данных ещё не реализовано.

Домашняя работа Занятие 01

Расширяем Task Tracker

Удаление

Добавьте кнопку удаления у каждой задачи. Удаляйте по id, а не по тексту.

Выполнение

Добавьте checkbox: задачу можно выполнить и вернуть в работу. Отличайте выполненные визуально.

Статистика

Покажите количество выполненных и невыполненных задач. Числа должны обновляться при каждом действии.

  • Проверьте удаление одной из двух задач с одинаковым текстом и удаление последней задачи.
  • Сдайте исходники проекта и краткую инструкцию запуска; node_modules прикладывать не нужно.
Подсказки к ДЗ Занятие 01

Обновляем данные без мутаций

// Удалить по id:
setTasks(prev => prev.filter(task => task.id !== id));

// Переключить выполнение:
setTasks(prev => prev.map(task =>
  task.id === id ? { ...task, done: !task.done } : task
));

// Вычислить внутри App перед return:
const completed = tasks.filter(task => task.done).length;
const remaining = tasks.length - completed;
Обратите внимание

id передайте в обработчик выбранной задачи. Счётчики вычисляйте из tasks при рендере: отдельное состояние для них не нужно.
